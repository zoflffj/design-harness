# 수작업 과정

AI 없이 직접 수행했던 작업 과정을 정리한다. 서비스 목적을 정의한 [story-service.md](story-service.md)와 구분하며, 이 문서는 실제 작업 순서와 산출물, 확정된 필수 게이트를 다룬다.

## 작업 흐름

| 순서 | 작업 / 게이트 | 산출물 또는 확인 대상 | 결정 방식 |
|---|---|---|---|
| 1 | 나는 uibowl에서 경쟁사 레퍼런스를 수집한다. | 경쟁사 레퍼런스 모음 | — |
| 2 | 나는 레퍼런스를 분석하고 우리 서비스에 반영할 부분을 추린다. | 레퍼런스 분석 내용, 서비스 반영 항목 | — |
| 3 | **필수 게이트 ①: 레퍼런스 분석 → 화면 설계** | 분석 내용, 서비스 반영 항목 | 운영자가 재량으로 통과 여부 결정 |
| 4 | 나는 분석 내용을 토대로 우리 서비스 화면 설계 문서를 구체화한다. | 서비스 화면 설계 문서 | — |
| 5 | **필수 게이트 ②: 화면 설계 → 디자인 제작** | 화면 설계 문서 | 운영자가 재량으로 통과 여부 결정 |
| 6 | 나는 레퍼런스와 화면 설계 문서를 반영한 UI 키스크린 2~3개를 Figma에서 390×844 크기로 그린다. | UI 키스크린 2~3개 | — |
| 7 | 나는 내부 관계자들과 협의한 후 컨셉 시안을 확정한다. | 확정된 컨셉 시안 | 내부 관계자 협의·컨펌 |
| 8 | 나는 컨펌된 시안을 기반으로 디자인 토큰과 컴포넌트를 제작하고 화면을 디자인한다. | 디자인 토큰, 컴포넌트, 화면 시안 | — |
| 9 | 나는 완성된 시안의 토큰이나 컴포넌트가 우리 가이드를 위반하는지 검토한다. | 완성된 시안의 토큰·컴포넌트 | 가이드 위반 여부 검토 |

## 확정 사항

- 레퍼런스 분석과 화면 설계 사이, 화면 설계와 디자인 제작 사이에 필수 게이트를 둔다.
- 두 필수 게이트는 운영자가 재량으로 통과 여부를 결정하며, 승인 후 다음 작업으로 진행한다.
- 에이전트 경계는 두지 않는다.
- 기존 내부 관계자 컨펌과 최종 가이드 위반 여부 검토는 유지한다.
- 최종 검토 결과를 별도 문서로 작성하는지는 정해지지 않았다.
